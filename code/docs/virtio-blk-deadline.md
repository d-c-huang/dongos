# VirtIO 块设备计时完成等待

G6新编译器两次实际运行均返回编译成功，但随后FLUSH在原100000次轮询限制下失败（0x05030007），持久化未完成。原始失败与各700份转储独立审计保留。

生产block_service改用显式read_sectors_timed/write_sectors_timed/flush_timed，借用其已有milliseconds单调时钟回调。每个请求发布前读取起点；真实完成在5000ms内才可接受，与既有AHCI/NVMe命令时限一致。它替换该新入口的迭代计数限制，不修改G6的3600秒整体预算或P2屏障期限。

发布前时钟回调失败不写DMA或发布请求；发布后时钟错误、倒退、连续100000次不进展或真实到期都进入原失败持有路径。完成字段校验后再次读取时间，过期完成不获得ACK、不清fault、不释放DMA；真实reset成功之后才允许原close/release。起点接近u64上限时不用start+timeout加法，时钟回绕按倒退拒绝。

State 288B、Ops 40B、Lease 32B布局保持；原read/write/flush接口仍使用原计数策略，tablet共用接口不变。真实FLUSH请求、writeback/no-flush配置及完成length/id/status校验不改。

永久原生模型保留13旧场景，新增11计时场景：150001次poll后在期限内完成、4999/5000/5001ms、回调错误/倒退/冻结、迟到完成不复活、发布前失败原子性、近u64上界，以及读取完成字段期间跨越截止时间。debug/release真实生产坏体须分别拒绝绕过deadline、恢复旧poll上限和省略完成后的截止复查；原错误used-id和提前release坏体保留。两对象格式及布局门禁保持。

初次预检3项中延迟夹具第二次操作的模拟时钟回退导致两失败；第二轮新增旧计数坏体缺unsafe块而编译拒绝。两轮结果保留，修正夹具后第三轮4项/23.816秒/零skip通过，含两模式24场景、布局/ELF/COFF和五类真实坏体。正式隔离复验及新G6客体结果以协调器及后继回执为准，不提前声明客体通过。
